# 국가 운영 시뮬레이터

분기(1턴 = 1분기) 단위로 진행되는 국가 운영 시뮬레이션입니다.
경제·재정·인구·정치·외교·군사 시스템이 서로 영향을 주고받는 **시뮬레이션 엔진**이 이 프로젝트의 중심이고,
UI 는 그 엔진의 상태를 읽어 보여주는 얇은 계층입니다.

외부 AI API 는 사용하지 않습니다. 모든 판정은 seed 기반 결정적 계산으로 이루어집니다.

## 실행

```bash
npm install
npm run dev          # http://localhost:3000
npm run verify       # typecheck + lint + test
npm run build        # 정적 내보내기 (out/) — Vercel / Cloudflare Pages 배포용
npm run build:single # 단일 파일 index.html 생성 (dist/index.html, 저장소 루트 index.html)
```

`index.html` 은 CSS·JS 가 모두 인라인된 단일 파일입니다. 웹서버에 파일 하나만 올리면 게임이 동작합니다.

## 설계 원칙

- **UI 와 시뮬레이션 로직의 완전 분리.** `src/simulation` 은 React·Next.js·Zustand 를 import 할 수 없습니다.
  ESLint 의 `no-restricted-imports` 규칙이 이를 강제하므로, 의존이 생기면 빌드가 실패합니다.
- **순수 함수 중심.** 모든 계산 모듈은 입력을 받아 새 값을 돌려주며, 상태를 변형하지 않습니다.
- **결정적 시뮬레이션.** 같은 초기 상태 + 같은 seed + 같은 조작이면 항상 같은 결과가 나옵니다.
  난수는 `deriveRng(seed, turn, 채널, 국가)` 로 채널별 독립 스트림을 만들기 때문에,
  나중에 시뮬레이션 단계가 추가돼도 기존 세이브의 재현성이 깨지지 않습니다.
- **계수의 분리.** 밸런스에 관여하는 모든 숫자는 `src/config` 에 있습니다. 로직 파일에 매직 넘버를 두지 않습니다.
- **NaN·Infinity 차단.** 모든 계산은 `safe()` / `clamp()` 를 통과하며, 음수 GDP·음수 인구는 구조적으로 발생하지 않습니다.

### 핵심 설계: calibration

시뮬레이션의 모든 목표치 함수는 `f(정책·상태) + offset` 형태입니다.
게임 시작 시 `offset = 초기값 − f(초기 정책·상태)` 로 **역산**하기 때문에,
8개국이 서로 다른 출발점을 가지면서도 게임을 시작하자마자 제멋대로 흘러가지 않습니다.
그래서 이후에 나타나는 모든 변화는 **플레이어의 정책 변화와 이벤트로만** 설명됩니다.

예외는 생산성입니다. 생산성만은 국가별 추세성장률을 만들어 낼 만큼의 갭을 일부러 남겨 두고,
교육·연구개발 예산이 그 갭을 넓히거나 좁히도록 설계했습니다.
덕분에 교육 투자는 즉시 GDP 를 밀어 올리는 대신, 수 년에 걸쳐 잠재성장률을 바꿉니다.

`offset` 을 역산할 때는 반드시 clamp 이전의 원시값(`*Raw` 함수)을 씁니다.
clamp 된 값으로 역산하면 상한에 걸린 국가의 보정값이 어긋나기 때문입니다.

```
src/

  simulation/   시뮬레이션 엔진 — React 의존성 없음

    population/   출산·사망·이민·연령구조·교육
    government/   지지율·안정성·정책 검증·정책 효과 미리보기

    ai/           AI 국가의 rule-based 의사결정

    state/        게임 생성 · calibration 역산
    engine/       턴 오케스트레이션 (16단계)
  config/       모든 밸런스 계수와 국가 초기 데이터
  types/        도메인 타입
  lib/          저장(zod 검증)·Supabase 인증·표시 포맷터

  standalone/   단일 파일 번들 진입점
  tests/        시뮬레이션 엔진 단위 테스트
```

## 턴 진행 순서

`advanceTurn()` 은 아래 순서를 그대로 따르며, 각 단계는 독립 모듈에 위임합니다.

1. 정부 정책 적용 (AI 국가는 이 시점에 결정)
2. 세입 계산 → 3. 정부 지출 → 4. 재정수지
3. GDP 성장률 → 6. 물가 → 7. 실업률
4. 인구 변화 → 9. 생산성·경쟁력
5. 국가부채 → 11. 지지율·안정성
6. 외교 관계 → 13. 군사·전황
7. 랜덤 이벤트 → 15. 뉴스 → 16. 다음 턴

잠재성장률만은 **직전 분기에 확정된** 생산성·노동력 증가율을 씁니다(지표 공표 시차).

## 경제 모델 요약

- `성장률 = 잠재성장률 + 수요충격`, 수요충격은 세율·재정지출 변화·실질금리·물가·정치안정성·
  실업갭·산업경쟁력·무역수지 변화·전쟁·이벤트의 합입니다. 각 항의 기여도는 UI 에서 분해해 볼 수 있습니다.
- `C + I + G + (X − M) = Y` 항등식을 매 턴 정확히 유지합니다.
  정부지출(G)에는 예산 중 **정부가 직접 구매하는 부분만** 들어가고, 복지 같은 이전지출은 가계 소비로 흡수됩니다.
- 물가는 기대인플레이션 + 필립스 곡선 + 수요압력 + 통화정책 + 소비세 전가 + 에너지 충격으로 결정됩니다.
- 실업률은 오쿤의 법칙으로 움직이고, 구조적 실업률로 서서히 수렴합니다.
- 금액은 모두 실질(불변가격) 기준이므로, 물가상승은 실질 국가부채를 줄이는 방향으로 작용합니다.
- 기준금리는 기본적으로 **중앙은행이 테일러 준칙에 따라 자동 운용**합니다.
  직접 운용으로 바꾸면 물가 안정 책임도 함께 지게 됩니다.

## 저장

`localStorage` 기반이며, 저장 데이터는 **zod 스키마로 전량 검증**한 뒤에만 사용합니다.
JSON 파싱 실패, 범위를 벗어난 비율, `null`/비유한 값, 버전 불일치는 모두 거부됩니다.
`version` 필드가 있어 향후 마이그레이션이 가능합니다.

Google 로그인(Supabase OAuth)을 하면 저장 슬롯이 계정 ID 네임스페이스로 분리되어,
같은 브라우저에서 여러 사람이 각자의 진행 상황을 유지할 수 있습니다.
로그인하지 않아도 게임의 모든 기능은 그대로 동작합니다.

> 로그인은 http(s) 오리진에서만 동작합니다. `index.html` 을 `file://` 로 직접 열면
> 게임은 정상 동작하지만 OAuth 리디렉션은 사용할 수 없습니다.

## 테스트

```bash
npm run test
```

Arrange–Act–Assert 로 작성했고, 다음을 검증합니다.

- 세율 인상 시 세입 변화와 래퍼 곡선의 단조성
- 정부 지출 증가 시 국가부채 변화, 물가에 의한 실질부채 감소
- 교육 투자의 단기/장기 효과 차이
- 과도한 물가 상승 시 지지율 하락, 요인별 기여도 상한
- 인구가 음수가 되지 않는지, GDP 가 NaN 이 되지 않는지, 지지율이 0~100 을 벗어나지 않는지
- 동일 seed 에서 60분기 진행 결과가 완전히 동일한지 (뉴스·이벤트 이력 포함)
- 랜덤 이벤트의 결정성, 이벤트 선택 전에는 턴이 넘어가지 않는지
- 저장 데이터 검증(파싱 실패·범위 초과·버전 불일치 거부)과 복원 후 진행 결과 일치
